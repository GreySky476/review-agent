# 安全编码规范

> 文档版本：v1.0 | 更新日期：2026-06-08 | 关联文档：[API 规范](../api/conventions.md)、[部署运维](../deployment/ci-cd.md)

---

## 一、凭证管理

### 1.1 加密存储

- Token、Webhook Secret 使用 **AES-256** 加密存储
- 推荐托管至 HashiCorp Vault 或云平台 Secret Manager
- **日志禁止输出明文凭证**

### 1.2 密钥轮换

- 支持定期轮换和手动失效
- Webhook Secret 可在管理后台重置

### 1.3 环境变量

- 敏感配置通过环境变量注入（非配置文件）
- 使用 `.env.example` 模板说明所需变量（不含真实值）

---

## 二、代码数据保护

### 2.1 传输安全

- 所有外部通信使用 HTTPS
- 证书自动续期（Let's Encrypt / 云平台托管）

### 2.2 存储加密

- 数据库中代码内容可选加密存储
- 对象存储（MinIO / S3）启用服务端加密
- 支持内网部署 + 私有模型，代码数据不出企业边界

### 2.3 数据保留

- 原始事件和评审报告默认保留 90 天
- 保留策略可在项目级别配置
- 归档数据可导出后清理

---

## 三、访问控制

### 3.1 管理后台

- 强制登录认证
- 支持 OIDC / SAML 单点登录
- 权限分三级：

| 角色 | 权限 |
|------|------|
| 超管 | 系统全局配置、用户管理、审计日志 |
| 项目管理员 | 仓库管理、规范管理、全量评审记录 |
| 查看者 | 仅本人参与的评审记录 |

### 3.2 报告访问

- 评审报告链接携带 **临时 Token**
- 有效期默认 7 天（可配置）
- Token 范围限制：仅指向单个报告

---

## 四、审计日志

- 记录所有敏感操作：登录、配置修改、Token 重置、权限变更
- 日志字段：操作人、时间、IP、操作类型、结果
- 日志保存至少 **180 天**
- 支持日志导出（JSON 格式）

---

## 五、CI/CD 安全门禁

### 5.1 代码扫描

| 检查项 | 工具 | 阻塞发布 |
|--------|------|---------|
| 硬编码密钥检测 | `truffleHog` / `git-secrets` | ✅ |
| 依赖漏洞扫描 | `pip-audit` / `safety` | ✅ |
| SAST | `bandit` / `semgrep` | ✅ |
| 容器镜像扫描 | `trivy` | ✅ |

### 5.2 禁止项

- 禁止 `console.log` 提交（前端）
- 禁止 `// TODO`、`FIXME`、`HACK` 提交到 `main`
- 禁止硬编码密钥、Token、密码

---

## 六、AI 模型安全

| 风险 | 缓解措施 |
|------|---------|
| Prompt 注入 | 评审 prompt 中明确角色边界，对用户代码内容转义处理 |
| 敏感数据泄露 | 模型只接收代码 diff，不接收仓库名、作者等元信息 |
| 模型幻觉 | 所有安全性 Finding 要求引用具体代码行，降低误报 |
| 私有化模型 | 支持 vLLM 部署开源模型，确保代码不出企业网络 |

---

## 七、运行时安全

### 7.1 熔断与降级

- LLM 调用：30s 超时，重试 1 次，连续 5 次失败熔断 2 分钟
- Git 平台 API：令牌桶限流 ≤ 官方频率的 70%
- 全局降级开关：可暂停所有自动评论，仅生成后台报告

### 7.2 输入验证

- Webhook 请求体严格按 Pydantic 模型校验
- 文件路径遍历防护：禁止 `../` 等特殊路径
- 所有用户输入输出 HTML 转义
