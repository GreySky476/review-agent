# 通用代码评审规范

> 文档版本：v1.0 | 适用语言：其他语言（未单独定义规范的兜底规则）

---

## 1. 资源管理 <critical>

### 1.1 外部资源
- 文件句柄、网络连接、数据库连接、锁资源使用后必须释放
- 优先使用语言自带的 RAII / 上下文管理器 / try-finally 模式管理资源
- 显式管理连接池的创建和销毁

### 1.2 内存管理
- 确保动态分配的内存有正确的释放路径
- 避免显式内存管理时的 double-free / use-after-free
- 大型对象不再使用时及时置空以便 GC

---

## 2. 并发安全 <critical>

### 2.1 共享状态
- 多线程/多协程访问共享变量必须使用同步原语保护
- 避免使用裸系统线程，优先使用线程池/协程
- 原子操作优于锁（适用场景下）

### 2.2 竞态条件
- check-then-act 模式必须加锁保护
- 延迟初始化必须正确处理竞态（double-checked locking 模式）
- 避免死锁：始终按相同顺序获取多个锁

---

## 3. 正确性 <warning>

### 3.1 错误处理
- 禁止裸 catch/except 捕获所有异常
- 异常/错误必须有具体的类型或条件
- 不要在 catch 块中静默吞掉异常（至少记录日志）
- 函数返回值必须始终检查（尤其是可能返回 null/error 的场景）

### 3.2 常见陷阱
- 避免使用可变值作为默认参数/属性
- 比较浮点数时使用 epsilon 而非精确相等
- 字符编码必须显式处理，禁止依赖系统默认
- 循环中修改正在迭代的集合必须使用副本

---

## 4. 安全 <warning>

### 4.1 注入防护
- 所有动态查询必须使用参数化查询或预编译语句
- 禁止直接拼接用户输入到命令/查询字符串中
- 模板/渲染引擎必须开启自动转义

### 4.2 危险操作
- 禁止动态执行/编译用户提供的代码字符串
- 系统命令调用必须使用列表参数而非字符串拼接
- 反序列化不可信数据时使用安全的序列化格式

### 4.3 敏感信息
- 禁止硬编码密钥、Token、密码在源码中
- 日志中必须脱敏处理敏感字段（密码、Token、身份证号等）
- 使用环境变量或 secrets 管理工具加载敏感配置

---

## 5. 性能 <info>

### 5.1 算法效率
- 避免循环内执行重复计算（提取到循环外）
- 批量数据处理优先选择语言内置的高阶函数
- 高频路径中使用适当的数据结构（HashSet 优于 List 的 contains）

### 5.2 IO 优化
- 避免 N+1 查询模式，使用批量请求/预加载
- 文件操作使用缓冲读写
- 避免在热点路径中执行昂贵的 IO 操作

---

## 6. 代码规范 <info>

### 6.1 命名规范
- 函数/方法：遵循语言惯例（camelCase 或 snake_case）
- 类名：PascalCase
- 常量：UPPER_CASE
- 命名要清晰表达意图，避免缩写（除非广泛公认）

### 6.2 函数设计
- 单个函数不超过 **50 行**（硬上限 100 行）
- 圈复杂度不超过 **10**
- 参数不超过 **5 个**（超过考虑使用配置对象）
- 嵌套层级不超过 **4 层**

### 6.3 模块设计
- 遵循单一职责原则
- 避免循环依赖
- 公共 API 必须有文档注释说明输入输出
